# Chrome オンデバイス LLM チャット "Hitorigoto" 仕様書

Sep 27, 2026 · @Masataka Koguchi

## 1. 概要と目的

Chrome 内蔵の Prompt API（Gemini Nano）だけで動く、サーバーを持たない LLM チャット Web アプリ「Hitorigoto」（ひとりごと）を開発する。名称は、話し相手が手元のモデルだけで、入力が端末の外に出ないことを表す。入力も履歴も端末の外に出ないことを、方針ではなく構造で保証するのが最大の価値である。

- **形態**: Web アプリ。Cloudflare Pages の静的ホスティングで配信する。
- **対象ユーザー**: Chrome（デスクトップ）でオンデバイスモデルを利用できる人。
- **履歴の保存先**: localStorage。履歴管理機能（一覧・検索・削除・エクスポート等）と、履歴をすぐ削除できる UI を備える。
- **UX の要**: オンデバイスモデル利用に伴う設定・環境要件の注意書きを、わかりやすく掲示する。UI 言語は日本語と英語を切り替えられる。
- **差別化**: SaaS ではないことの優位点（プライバシー、従量課金なし、アカウント不要、オフライン動作、データの所有）を機能に落とす。

**スコープ外（初期）**: クラウド LLM へのフォールバック、アカウント・同期、サーバーサイド機能、モバイル対応（Prompt API が非対応のため）。

## 2. 設計原則: 「送信しない」を検証可能にする

SaaS ではない LLM チャットの本質的な優位点は機能の多さではなく、データがサーバーに行かないことである。主張だけでは弱いので、ブラウザ側が強制する構造にする。

1. **CSP で外部通信を遮断**: `_headers` で `connect-src 'self'` を設定し、外部への通信をブラウザが拒否する。後から分析タグを足しても動かない。
2. **外部依存を持たない**: フォント・画像・スクリプトは自前ホスト。CDN、外部分析（Cloudflare Web Analytics を含む）は使わない。
3. **検証手順を画面に明記**: 「送信データ 0 バイト。DevTools の Network タブで確認できます」と手順まで示す。
4. **クラウド LLM へのフォールバックを入れない**: 入れた瞬間に CSP の保証が崩れ、優位点が消える。非対応環境では、使えない理由と対処を丁寧に示すだけにする。
5. **ストレージ層を抽象化**: `HistoryRepository` インターフェースで localStorage を包み、将来 IndexedDB へ UI を変えずに差し替えられるようにする。

## 3. 対象環境と前提

Prompt API は Chrome 148 で stable になったが、動作にはハードウェア要件があり、利用できないユーザーが一定数いる。要件は Chrome 公式ドキュメント（[Get started with built-in AI](https://developer.chrome.com/docs/ai/get-started)）に基づく。

| 項目 | 要件・仕様 |
| --- | --- |
| OS | Windows 10/11、macOS 13 以降、Linux、Chromebook Plus。Android・iOS は非対応 |
| ストレージ | Chrome プロファイルのあるボリュームに 22GB 以上の空き。ダウンロード後に空きが 10GB を下回るとモデルは削除され、条件を満たすと再ダウンロードされる |
| GPU | VRAM が 4GB 超 |
| CPU（GPU なしの場合） | RAM 16GB 以上、かつ 4 コア以上 |
| ネットワーク | 従量制でない接続。通信が必要なのは初回のモデルダウンロード時のみ |
| 言語 | Chrome 149 以降、入出力で英語・スペイン語・日本語・ドイツ語・フランス語に対応 |
| ダウンロードの起点 | `availability()` が `downloadable` / `downloading` のとき、`create()` の呼び出しにはユーザーの操作（クリック、キー入力等）が必要 |

**プライバシー上の前提**: モデル使用中に Google や第三者へデータは送信されない（公式ドキュメントの記述）。

**能力の前提**: Gemini Nano は小型モデルで、長文推論や高い事実性は期待できない。「オートコンプリート級」の用途（推敲、要約、分類、アイデア出し）を想定し、画面上でも得意・不得意を示す。

## 4. 技術スタック

チャット UI は assistant-ui、Markdown 描画は Streamdown を軸にし、ビルドは Vite + React + TypeScript の静的出力とする。

| 層 | 採用 | 選定理由 |
| --- | --- | --- |
| チャット UI | [assistant-ui](https://github.com/assistant-ui/assistant-ui) | Thread / Message / Composer / ThreadList 等のプリミティブで構成。ストリーミング、自動スクロール、再試行、添付、Markdown、コードハイライト、アクセシビリティを標準搭載。ThreadList が履歴管理 UI の土台になる |
| Markdown 描画 | [Streamdown](https://streamdown.ai/docs) | react-markdown のドロップイン代替。閉じていないコードフェンスや書きかけの表でも表示が崩れない |
| スタイル | Tailwind + shadcn/ui | assistant-ui の CLI が shadcn/ui ベースのテーマ（Base UI または Radix）を取り込む |
| ビルド | Vite + React + TypeScript | 静的出力のみ。Next.js を使う場合は `output: 'export'` |
| ホスティング | Cloudflare Pages | 静的配信、`_headers` で CSP を設定。Functions は使わない |
| 推論 | Chrome Prompt API（`LanguageModel`） | オンデバイス。自前ランタイムで assistant-ui に接続する |

**不採用とした候補**

- **Vercel AI Elements**: AI SDK の `useChat` 前提の設計で、サーバーを持たず Prompt API を直接使う本構成とは相性が良くない。
- **shadcn/ui のチャット部品（2026 年 6 月公開）**: MessageScroller 等は思想が近いが、公開直後でスクロールの不具合報告があり、初期採用は見送る。将来スクロール部品だけの差し替え候補とする。
- **Prompt API の polyfill**: クラウド推論へ逃がす仕組みを含み得るため、「送信しない」原則に反する。使用しない。

**依存ライブラリの禁止事項**: assistant-ui の Assistant Cloud（スレッド永続化・分析のクラウド）は使用しない。Shiki の文法ファイルや WASM、Mermaid を実行時に外部取得する構成も禁止し、必要ならバンドルに含める。

## 5. アーキテクチャ

UI・ランタイム・推論・保存をレイヤで分け、データの経路をブラウザ内に閉じる。

&#91;embedded content: 構成図 · 4 レイヤ + 配信元\]

Cloudflare Pages が配信するのは静的ファイルだけで、推論と履歴はすべてユーザーの Chrome 内で完結する。

| レイヤ | 責務 |
| --- | --- |
| チャット UI | assistant-ui の Thread / Composer / ThreadList を組み、Streamdown で描画する |
| 自前ランタイム | assistant-ui と Prompt API をつなぐ。起動診断、ストリーミング、停止、コンテキスト管理を担う。メッセージの正は自前ストアの `messages[]` とし、Nano のセッションは作り直し可能にする |
| HistoryRepository | 履歴の保存・検索・エクスポートの窓口。実体は localStorage で、IndexedDB へ差し替え可能 |
| Prompt API | `LanguageModel` 経由で Gemini Nano を呼ぶ |

assistant-ui への接続方式（ローカル型または外部ストア型のランタイム）は、ローカル型を第一候補とする。実装着手時に公式ドキュメントで要件を確認し、履歴を自前ストアで持つ設計と噛み合わない場合は外部ストア型に切り替える。

## 6. 起動診断と注意書き UX

利用できない理由を切り分けて表示することが、このアプリで最もつまずきやすい箇所の対策になる。`availability()` は `unavailable` を返すだけで理由までは教えないため、原因の候補を順に示すチェックリスト形式にする。

**診断フロー**

1. `'LanguageModel' in self` が false → Chrome 以外、または古いバージョン。Chrome 148 以上への更新を案内する。
2. `availability()` の結果で分岐する。
   - `unavailable` → 要件チェックリストを表示する。
   - `downloadable` → 「モデルをダウンロード」ボタンを表示する（ユーザー操作が `create()` の起点になる）。
   - `downloading` → `monitor` の `downloadprogress` で進捗バーを表示する。
   - `available` → チャット画面へ進む。

**注意書きに掲示する内容**

| 項目 | 掲示内容 |
| --- | --- |
| 対応環境 | デスクトップ Chrome（Windows 10/11、macOS 13+、Linux、Chromebook Plus）。Android・iOS は非対応 |
| 空き容量 | Chrome プロファイルのドライブに 22GB 以上。ダウンロード後に 10GB を下回るとモデルが削除される点も併記 |
| 性能 | GPU なら VRAM 4GB 超。GPU なしなら RAM 16GB 以上かつ 4 コア以上 |
| 回線 | 従量制でない接続を推奨。初回のみ数 GB のダウンロードが発生する |
| 初回の流れ | ボタン操作でダウンロードを開始し、完了まで待つ必要がある |
| 状態確認 | `chrome://on-device-internals` で確認できる |

**実装上の注意**

- Web ページから `chrome://` へのリンクは開けない。URL は「コピー」ボタン付きのテキストで示す。
- 「使えない理由」は断定できない。「次のいずれかが原因の可能性があります」という書き方にする。
- 診断結果は折りたたみで残し、設定画面から再確認できるようにする。
- チャット画面の上部にステータスバッジ（オンデバイス｜オフライン可｜送信 0）を常時表示する。

## 7. チャットコア機能

コンテキスト長の制約が最大の設計要因であり、メッセージ履歴の正を自前で持つことで、セッション再作成に耐える構造にする。

```js
const session = await LanguageModel.create({
  initialPrompts: [{ role: 'system', content: systemPrompt }],
  temperature, topK,
  expectedInputs:  [{ type: 'text', languages: ['ja', 'en'] }],
  expectedOutputs: [{ type: 'text', languages: ['ja'] }],
  signal: abortController.signal,
});
for await (const chunk of session.promptStreaming(userText)) { /* 逐次描画 */ }
```

| 機能 | 仕様 |
| --- | --- |
| ストリーミング | `promptStreaming()` の出力を逐次描画する。表示は Streamdown で崩れを防ぐ |
| 停止・再生成 | `AbortController` で停止。再生成と、編集して再送信に対応する |
| メッセージの正 | 自前ストアの `messages[]` を正とし、Nano のセッション内部履歴には依存しない |
| コンテキスト管理 | `inputUsage` / `inputQuota` を監視して残量ゲージを表示する。閾値（例: 80%）で古いターンを要約し、「要約 + 直近 N ターン」を `initialPrompts` に入れた新セッションへ切り替える |
| 分岐 | `session.clone()` で会話を分岐する |
| パラメータ | `LanguageModel.params()` の範囲に合わせて温度・topK のスライダーを設ける |
| 構造化出力 | `responseConstraint` に JSON Schema を渡し、分類・抽出などの用途に使う |
| セッション破棄 | 使い終わったセッションは `destroy()` する |
| 用途別テンプレート | 推敲、要約、分類、アイデア出しなど Nano の得意領域を示すテンプレートを用意する |

API の細部（メソッド名・パラメータ）は Chrome のバージョンで差があり得るため、機能検出で防御し、実装前に公式の Prompt API ドキュメントで確認する。

### 7.1 応答待ちの体感対策（止まっていないことを示す UI）

オンデバイスの Nano は、クラウドの SaaS より待ち時間が長くなる場面がある。速度そのものは変えられないため、待ち時間を「段階ごとに、いま何が起きているか」を見せることで、停止していないことを伝える。

| 段階 | ユーザーに見せるもの | 実装メモ |
| --- | --- | --- |
| モデルのダウンロード | 進捗バーと割合、「初回のみ・数 GB」の説明 | `monitor` の `downloadprogress` を表示する |
| セッション作成（モデルの読み込み） | 「モデルを読み込み中」のスピナーと、初回は時間がかかる旨の一文 | `availability()` が `available` になった時点で先にセッションを作成し、ユーザーが入力している間に読み込みを終わらせる |
| 送信直後 | 送信したメッセージを即座に表示し、応答欄にタイピング表示（3 点アニメーション）またはスケルトンを出す | 入力から表示までの遅延を出さない。応答の生成を待たずに UI を更新する |
| 最初のトークンまで | 「考え中…」と、3 秒を超えたら経過秒数のカウンター | 経過時間を表示するだけで、体感の不安が大きく減る |
| ストリーミング中 | 文字が流れる表示、点滅するカーソル、目立つ「停止」ボタン | 描画は `requestAnimationFrame` で間引き、履歴側のメッセージは再描画しない（メモ化） |
| 長い無応答 | 一定時間チャンクが来なければ「応答が止まっているようです」と表示し、「停止」「再試行」を出す | 閾値は実測して決める |
| 会話の要約中 | 「会話を要約しています」（コンテキスト管理の処理中であることを明示） | 要約中は送信を待たせるか、キューに積む |

**補足**

- 待機中の表示には「端末内で処理中（送信なし）」を添える。待たされる理由が、プライバシーの優位点として伝わる。
- アクセシビリティ: 状態の文言は `aria-live="polite"` の領域に出す。アニメーションは `prefers-reduced-motion` を尊重する。
- 計測: 最初のトークンまでの時間と、生成速度（トークン/秒）を端末内だけで記録し、デバッグ用パネルで確認できるようにする（外部へは送信しない）。この実測値で、上表の閾値を決める。

## 8. 履歴管理（localStorage）

履歴は localStorage に保存する。容量は通常 5MB 前後で、同期 API のため、上限に達したときの扱いと、消えうることの周知を仕様に含める。履歴は暗号化せずに保存し、その代わりに即時削除の導線を厚くする。

**データ構造**

- `index` キー: スレッド一覧のメタデータ（id、タイトル、更新日時、ピン留め、メッセージ数、概算サイズ）。
- `thread:{id}` キー: 各スレッド本体。
- `schemaVersion` を持たせ、マイグレーションを前提にする。
- `HistoryRepository` で抽象化し、容量が足りなくなったら UI を変えずに IndexedDB へ差し替える。

**履歴管理機能**

| 機能 | 仕様 |
| --- | --- |
| 一覧・切替 | assistant-ui の ThreadList を土台にする |
| 検索 | タイトルと本文の全文検索 |
| 整理 | ピン留め、リネーム、削除、一括選択削除。削除後の数秒間は「元に戻す」を提示する。加えて、どの画面からも 1〜2 操作で到達できる「全履歴を削除」（確認ダイアログ付き）を常設する |
| タイトル自動生成 | Nano による生成。遅いので任意設定にする |
| 使用量メーター | 「使用 1.2MB / 約 5MB」形式で表示し、80% 超で警告する |
| 容量エラー | `QuotaExceededError` を必ず捕捉し、「書き込めませんでした。エクスポートして古いスレッドを削除してください」と明示する。黙って失敗させない |
| エクスポート | 全体を JSON、個別スレッドを Markdown で出力する |
| インポート | ID 衝突時に「マージ」か「別名で保存」を選べる |

**localStorage 特有の注意（画面にも掲示する）**

- ブラウザの「サイトデータ削除」で履歴が消える。定期的なエクスポートを促す。
- オリジンごとに分離される。`*.pages.dev` からカスタムドメインへ移行すると履歴が見えなくなるため、将来ドメインを変える場合はエクスポート/インポートで対応する。
- 複数タブでは `storage` イベントで同期し、同時書き込みと推論の同時実行を制御する。

## 9. 非 SaaS の優位点を活かす機能

SaaS にはない性質を、それぞれ具体的な機能へ落とす。

| 優位点 | 機能 |
| --- | --- |
| 完全プライベート | 「保存しないチャット」（一時チャット）モード、全データ消去ボタン。機微な内容の下書き用途を明示する |
| 従量課金・レート制限なし | 再生成に回数制限を設けない。同じ入力を温度違いで並べて比較する「複数案生成」 |
| アカウント不要 | 初回から即利用でき、ログインを求めない |
| オフライン動作 | PWA 化し、Service Worker で静的資産をキャッシュする。モデルのダウンロード後は機内モードでも動く |
| データの所有 | JSON / Markdown で全履歴をエクスポート・インポートできる |
| 送信ゼロの検証 | CSP の設定内容と、DevTools の Network タブで確認する手順を説明するページを設ける |
| ファイルが外に出ない | 画像などの添付は端末内だけで処理する（マルチモーダル入力は後続フェーズ） |

これらの優位点はステータスバッジやトップページでも一貫して示し、「なぜ Nano を選ぶのか」をユーザーが理解できるようにする。

## 10. ホスティングとセキュリティ

Cloudflare Pages では静的ファイルのみを配信し、Functions は使わない。バックエンドを持たないことが、CSP による「送信ゼロ」の保証と整合する。

| 項目 | 仕様 |
| --- | --- |
| 配信 | 静的出力のみ。Functions・KV・D1 等のサーバー機能は使わない |
| CSP | `_headers` で設定。`connect-src 'self'` を基本とし、スクリプト・スタイル・フォント・画像も自オリジンに限定する |
| その他ヘッダー | `X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer` |
| 外部依存 | CDN、外部フォント、分析タグ（Cloudflare Web Analytics を含む）は使わない |
| WASM | Shiki 等が WASM を必要とする場合のみ、CSP に `'wasm-unsafe-eval'` を追加する。追加の要否は実装時に検証する |
| PWA | Service Worker は静的資産のキャッシュに限定する |
| ドメイン | 公開 URL は hitorigoto.pages.dev とする（サブドメインが取得できるかは、公開前に Cloudflare Pages で確認する）。localStorage はオリジン単位のため、`*.pages.dev` を想定する。カスタムドメインへ移す場合は、エクスポート/インポートで履歴を移行する |
| 依存管理 | 導入前に `npm audit` を実施し、新規依存を追加するたびに外部通信の有無を確認する |

**検証**: リリースごとに、DevTools の Network タブで外部リクエストがゼロであることを確認する。この手順は画面上の説明ページにも掲載する。

## 11. 実装フェーズとリスク

診断フローと保存の土台を先に固め、優位点の機能と拡張は後から積む。

| フェーズ | 範囲 |
| --- | --- |
| 1. MVP | 起動診断と注意書き、単一スレッドのストリーミングチャット、localStorage 保存、履歴一覧と削除、一時チャット、履歴の即時削除 UI、日英切替、応答待ち UI |
| 2. 管理機能 | 検索、ピン留め、リネーム、エクスポート/インポート、使用量メーター、容量エラー処理 |
| 3. 優位点の強化 | 複数案生成、PWA オフライン化、CSP 検証手順ページ |
| 4. 拡張 | 自動要約によるコンテキスト管理の高度化、画像入力、IndexedDB への移行 |

**主なリスクと対応**

| リスク | 対応 |
| --- | --- |
| 利用できない環境が一定数ある（22GB の空き、GPU/RAM 要件、モバイル非対応） | 診断フローで理由と対処を明示し、要件を注意書きに掲示する |
| Nano の能力が限定的で、期待とのギャップが生じる | 得意な用途のテンプレートを用意し、画面上で限界を示す |
| コンテキスト長の制約で長い会話が破綻する | 自前の `messages[]` を正とし、要約と新セッション化で継続する |
| localStorage の容量超過・データ消失 | 使用量メーター、容量エラーの明示、エクスポートの促し、IndexedDB への移行余地 |
| Chrome の更新でモデルや API の挙動が変わる | 機能検出で防御し、固定プロンプトの評価セットを Chrome の stable リリースごとに実行する |
| 依存ライブラリが実行時に外部通信する | 導入時に外部通信を検証し、Network タブでゼロ通信を確認する |

## 12. 決定事項と残課題

- [x] 一時チャット（履歴を保存しないモード）は MVP に含める。
- [x] 履歴の暗号化は行わない。代わりに、履歴をすぐ削除できる UI（常設の「全履歴を削除」、スレッド単位の削除）を用意する。
- [x] UI 言語は日本語と英語を切り替えられるようにする。
- [x] アプリ名は Hitorigoto（ひとりごと）、公開 URL は hitorigoto.pages.dev とする。公開ドメインは `*.pages.dev` を想定する。
- [ ] assistant-ui への接続はローカル型ランタイムを第一候補とする。着手時に要件との整合を確認し、合わない場合は外部ストア型に切り替える。
